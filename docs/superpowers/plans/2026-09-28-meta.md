# meta.pick3.gg design pass (Piece 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put meta.pick3.gg on pick3's header, tokens and components (Top teams, Pokémon,
Species, About), fix the Species moves share, let "Build a team around it" carry a Pokémon into
pick3's Build, and write the three audit records for Travis to sign.

**Architecture:** Shared pieces first: the cross-link button moves into `packages/ui` and pick3
learns the Build lead link. Then meta's pure copy helpers (names, the one blend line, row lines,
the moves share) are rebuilt under tests, then the shell (header, tabs, theme on About), then
each screen on those helpers. Captures, the enforced `meta:audit` and the records last.

**Tech Stack:** React 19, TypeScript 5.9 strict, vitest 4 + jsdom + Testing Library,
puppeteer-core capture and audit scripts, `@pickthree/ui`.

**Spec:** `docs/superpowers/specs/2026-09-28-design-meta-design.md` (all sections). Record
models: `docs/design/audits/counters.md`, `collection.md` (signed).

## Global Constraints

- Exact pinned versions; braces on all control flow; no em dashes anywhere (code, docs, commit
  messages, UI copy).
- "Pokémon" with the accent and "·" between the parts of a line, in meta's UI copy as in pick3's.
  Species and move names keep PvPoke's own spelling.
- Tokens only (`npm run check-colors`; rewrite the baseline with
  `node scripts/color-literals.mjs --write` only when a literal is removed); 44px touch targets;
  grep `apps/meta/src/app.css` and `packages/ui/base.css` before adding a class.
- Pink only for measured data, as text with its mark, never a pill (`MeasuredValue`,
  `MeasuredLine`). Projections say "Projected" and are never shown as a measured result. Small
  numbers are never hidden. The 300, 5, 100 and 2 half-say constants and the blend math are not
  touched.
- Tags are read, chips are tapped. At most one line of text before the first result;
  warnings (a `Note tone="warn"`) may sit above it.
- No change to `workers/counter`, the API, the bake, or `apps/meta/src/rank.ts`'s weighting. No
  new outbound call from pick3; the CSP is unchanged.
- The enforced audit fails a capture whose text is never on screen in any capture of its page and
  theme (NEVER); a list or sheet that scrolls needs a scrolled capture too.
- Stage explicit paths; commit messages: subject alone on line 1, a blank line, body, trailers
  (`Co-Authored-By` names your own model;
  `Claude-Session: https://claude.ai/code/session_01QpDSW9ZhLWToL3VMBP1mJq`); write the message to
  a file and `git commit -F`. Never kill a process you did not start.

## Rulings made while writing this plan

1. **One cross-link component:** `SiteLink({ site: 'meta' | 'pick3' })` in `packages/ui`, an
   `IconButton` with a fixed href, label and glyph: `meta` is `https://meta.pick3.gg`, label
   "meta.pick3.gg, the community meta", pick3's `MetaGlyph` (moved into ui); `pick3` is
   `https://pick3.gg`, label "pick3, the team builder", the pick3 mark (`brand/mark.svg` as an
   `<img>` at 20px, `alt=""`). An image keeps the mark's brand colors out of the color-literal
   check. [Cross-link.]
2. **Spelled names live in meta's `format.ts`** as `spelledName(pvpokeName: string): string`,
   the same rule as the engine's `fullName` done on the name string alone (meta has no
   `GameDataIndex`): strip every trailing `(Shadow)`, move one regional form (Alolan, Galarian,
   Hisuian, Paldean) to the front, then put "Shadow " first if it was a Shadow; any other form
   keeps its parentheses. `SpeciesLite.short` is removed and every `.short` read becomes `.name`,
   which `loadStatic` now fills with `spelledName(entry[0])`. [Names.]
3. **The ASCII rule is retired** per the spec: `ascii()` is no longer applied to rendered names
   or copy (`data.ts`); `assertAscii` in `apps/meta/scripts/screens.mjs` becomes
   `assertNoEmDash` (fails on U+2014 in `document.body.innerText`); the ASCII tests in
   `about.test.tsx` and `boardView.test.ts` become no-em-dash tests. `ascii()` itself is deleted
   if nothing else uses it. [Copy.]
4. **The one blend line** is `blendParts(r: SpeciesRanking): string[]` in `headerCopy.ts`, joined
   with " · " and followed by the `Term` "How it is ranked". The percentages use exactly the
   rounding `sourceHeaderLine` uses today, so the line and its explainer never disagree:
   - `prior`: `['PvPoke 100%']`;
   - `tournament`: no battles `['PvPoke 100%', 'No tournament battles yet']`, else with
     `t = round(tournamentSay * 100)`: `['PvPoke {100 - t}%', 'Tournaments {t}%']`;
   - `ladder`: no battles `['PvPoke 100%', 'No shared battles yet']`, else with
     `l = round(say * 100)`: `['PvPoke {100 - l}%', 'GBL {l}%']`;
   - `all`: `p = round((1 - say) * (1 - tournamentSay) * 100)`,
     `t = round((1 - say) * tournamentSay * 100)`, `l = round(say * 100)`; `PvPoke {p}%`, then
     `Tournaments {t}%` when `tournamentBattles > 0`, then `GBL {l}%` when `battles > 0`; with
     both zero, `['PvPoke 100%', 'No shared battles yet']`.
   The `Term` body is `sourceHeaderLine(...)` (today's sentence, unchanged), then the screen's
   own explainers: Top teams adds the sources line, the matchup score explainer and the coverage
   line; Pokémon adds the blend explainer and the "New" explainer. [Blend line.]
5. **Top teams row line** (`boardView.ts`'s `subLine`), parts joined with " · ":
   run and faced `'{n} battles'`, `'went {w}-{l}'`; faced only `'Faced in {n} battles'`,
   `'players went {facedLosses}-{facedWins}'`; run only `'Run in {n} battles'`, `'went {w}-{l}'`;
   no decided battle `'{n} battles'`, `'no result'`; a core adds `'{k} teams'` (`'1 team'`) when
   seen in any; a generated row returns `''` and the row shows the `Projected` tag instead.
   `battles` pluralises ("1 battle"). [Row line.]
6. **Pokémon's measured figure** is `MeasuredValue` (the ui's measured-number component, its
   mark is the bars; the render's dot was a mock of the same idea), value the share as a whole
   percent. The share, count and total come from one helper `facedFigure(row, ranking):
   { share: number; n: number; of: number } | null` extracted from today's `facedLine`: ladder
   and all read `sightings` of `ranking.battles`, tournament reads `tournamentPicks` of
   `ranking.tournamentBattles`; null when there is nothing to divide by, when `prior`, or when
   banned (the right side then shows today's plain words: "Not faced in this window", "Banned at
   tournaments", "No tournament battles in this window", in the muted color). [Measured figure.]
7. **Species hero** keeps the name as the page's `h1`-level title (a `<h2 className="hero-name">`
   in the page, not in the header), sprite 96px, `TypeChips`, then one `MeasuredLine`:
   ladder and all `'{p} of what players face · {n} of {N} battles'`, tournament
   `'{p} of tournament battles · {n} of {N} picks'`, where `p` is `pctFloor(share)`; the
   non-number states are a plain muted line with today's words. Under it, small and muted,
   "PvPoke #9" or "New". The "#1 of what players face" standing is dropped (the list's order
   already says it). [Hero.]
8. **Species back** is a button: when `window.history.state?.meta === 1` it calls
   `history.back()`, otherwise it navigates to the league's Pokémon list with `go()`. `go()`
   pushes `{ meta: 1 }` as the history state; `refine()` replaces with the current state kept.
   [Back.]
9. **The Build lead link** is `#/build?lead=<id>&l=<league>` parsed into
   `{ screen: 'build'; lead?: string; league?: string }` (both checked with `/^[a-z0-9_]+$/`,
   `l` only kept alongside `lead`). Build.tsx applies it the way Counters.tsx applies its linked
   league (the effect near its line 79): switch league if the named one is known and not in play;
   once it is in play and data is loaded, `setPick(0, { kind: 'species', id: lead })` when the
   species is in the list Build's own species picker offers for that league, then
   `navigate({ screen: 'build' }, { replace: true })` either way. `hashFor` writes the lead form
   back so parse and write round-trip. [Build lead.]
10. **Theme on About:** `App.tsx` keeps the theme state and passes `theme` and `onTheme` to
    `About`, which renders an "Appearance" card first with `Seg` (System, Dark, Light), values
    `ThemeChoice`. `ThemeIcon`, `appearanceLabel` and the header theme button go. [Theme.]
11. **Capture names** (all enforced, both themes, every fixture run where the page renders):
    `great` (Top teams), `great-open` (a row open, exists today), `great-sort` (the Sort list is
    a native select, so this is the page with Multi-team only on and Sort set to its second
    option), `great-ranked` (How it is ranked open), `pokemon`, `pokemon-tournaments`,
    `pokemon-pvpoke`, `pokemon-ranked` (How it is ranked open), `species-<DETAIL_SPECIES>`,
    `species-thin` (fewer than 3 weeks, no known moves), `species-missing` (not found), `about`.
    The `empty` run carries the empty board. [Names.]

## Review Focus

1. **A Species page opened from a shared link in a fresh tab:** Back lands on that league's
   Pokémon list on this site, never off-site or on a blank history entry (Task 5 test).
2. **Three long spelled names on one Top teams row** ("Shadow Alolan Ninetales, Galarian
   Stunfisk, Shadow Sableye"): the title truncates with an ellipsis and the score stays on the
   row at 390px (Task 6 test on the class, the captures' overflow check).
3. **A Build lead link opened before pick3 has finished booting, or naming an unknown league:**
   the lead still lands once data is ready; an unknown league is ignored and the lead applies in
   the league in play (Task 2 tests).
4. **A Species whose runs are known but whose moves are not** (`runs > 0`, every moveset with
   zero battles, or none): "No moves reported yet.", never "NaN%" or a share of zero (Task 4
   test).
5. **The theme chosen on About:** it applies at once, survives a reload and holds on every other
   page (Task 5 test through `storedTheme`).
