# Counters and Who Beats X (Piece 4, round 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Counters and Who Beats X one page on the foundation (an Against picker, a real back
from Your Meta, one line before the rows, labeled row links), show the full nine-cell shield grid
against one opponent, and write the Counters audit record for Travis to sign.

**Architecture:** The engine learns the grid first (nine battles per counter against one opponent,
the order by cells won), then the worker streams it (rows first, grids in batches). The Log a
Battle shield grid becomes a shared component. The route gains a `from` mark for the back, then
the page is rebuilt on `packages/ui`. Captures, the enforced audit and the record last.

**Tech Stack:** React 19, TypeScript 5.9 strict, vitest 4 + jsdom + Testing Library, the vendored
PvPoke simulator behind the engine's `BattleSimulator`, puppeteer-core audit scripts.

**Spec:** `docs/superpowers/specs/2026-09-26-design-rest-of-app-design.md` (sections "Decisions",
"App-wide rules applied here", "Counters (and Who Beats X)", "States", "Testing", "Records and
sign-off", "Cleanup"). Record models: `docs/design/audits/collection.md`, `settings.md` (signed).

## Rulings made while writing this plan

1. **The grid's inputs are the matrix's:** PvPoke default IVs and the rankings' recommended
   movesets for both sides, the league's CP and level cap, the same `SimOptions` the matrix build
   uses (`simOptionsFor(league)`). Ratings are the simulator's `rating` for the counter. [Inputs.]
2. **Grid order and rank:** in vs mode, after the 80 are chosen as today, entries sort by cells
   won out of nine (rating > 500), then the mean of the nine ratings, then PvPoke overall rank;
   `antiRank` is renumbered from that order. While grids are still filling, rows keep today's
   order; the final result re-sorts once. [Order.]
3. **Streaming:** the worker posts a `partial` counters result with the rows and `grid: null`,
   then a `partial` after each batch of 10 grids, then the `result` sorted by rule 2, carrying
   `gridMs` (milliseconds for all grids). The store keeps the newest partial for the same `vs` and
   league, and drops any that arrive after either changed. [Protocol.]
4. **The route's back mark** is `from=1` on the hash (`#/counters?vs=azumarill&from=1`), parsed
   into `{ screen: 'counters', vs, from: true }`; Your Meta's "Who beats it" links add it; the
   Against picker's replace-navigation keeps it. [Route.]
5. **The Against sheet searches the same species list Log a Battle's opponent search uses**, in
   the compact token grid, capped as it caps; "The whole meta" is a shortcut row below the results,
   hidden while the search has text. [Source.]
6. **The ownership filter is a `Seg`** (All, You own, Own or can build) in a ui `Sheet` titled
   "Filters", sticky key `counters.own`; the sort is `InlineSelect label="Sort"` (Best, Under the
   radar), sticky key `counters.sort`. The filter count is 1 when ownership is not All. [Controls.]
7. **Capture names** (all enforced, both themes): `08-counters` (whole meta), `counters-filters`
   (the Filters sheet), `18b-counters-no-collection`, `23-counters-vs` (from Your Meta, sub header,
   grids filled), `counters-vs-filling` (grids part-filled: the worker paused), `24-counters-vs-outsider`,
   `counters-against` (the sheet idle), `counters-against-search` (the sheet with a search),
   `counters-unranked` (an unranked opponent's empty state). `09-counters-own` goes (the chips are
   gone). `settings-hub-no-collection` moves back to the Counters no-collection cog, restoring the
   check that the Counters cog opens Settings. [Names.]

## Review Focus

1. **Changing the opponent in the Against sheet, then Back:** Back leaves Counters for where you
   came from (Your Meta), not through each opponent you tried.
2. **A meta.pick3.gg link with a league and an opponent on a fresh load:** the top header (no
   Back), the league switches first, and the grids are simulated in that league.
3. **Switching league while grids are filling:** the old league's grids never land on the new
   league's rows.
4. **Filters and sort after a trip to a Pokémon's page and back:** as they were, with the scroll.
5. **No collection:** no filter icon, the one-line Import link, and every row offers only "Build
   a team around it".
