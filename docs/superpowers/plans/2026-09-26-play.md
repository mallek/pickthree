# Play (Piece 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild Your Meta, Log a Battle and New Set on the design foundation, let a logged
battle's opponents and result be edited (resent to the counter worker, which now updates instead
of ignoring), show likely teammates while logging, and show what the player's battles contribute;
then one audit record per page for Travis to sign.

**Architecture:** Two data changes land first: the counter worker upserts a resent battle, and the
store gains `editBattle` plus an edit route for Log a Battle. Two pure helpers follow
(`contributedCount`, `likelyTeammates`). Then the three screens are rebuilt with `@pickthree/ui`,
Log a Battle first (Your Meta's result chips open its edit mode). Captures and records last.

**Tech Stack:** React 19, TypeScript 5.9 strict, vitest 4 + jsdom + Testing Library, Cloudflare
Worker + Durable Object (SQLite) tested through `workers/counter/test/sqliteShim.ts`,
puppeteer-core audit scripts.

**Spec:** `docs/superpowers/specs/2026-09-26-design-play-design.md`. Foundation:
`docs/superpowers/specs/2026-09-24-design-foundation-design.md`. Record models:
`docs/design/audits/teams.md`, `build.md`, `analysis.md` (all signed).

## Global Constraints

- Exact pinned versions; braces on all control flow; no em dashes anywhere (code, docs, commit
  messages); "Pokémon" with the accent in UI copy ("Poke Genie" keeps its own spelling).
- Tokens only (`npm run check-colors`); no class another screen already styles (grep
  `apps/web/src/app.css` first); 44px touch targets.
- Pink only for measured data: the contribution count is measured (a `MeasuredLine`); "Sharing is
  off" and the zero-sent line are plain text. Red only for destroying data: nothing on these pages
  destroys data, so no red button (Loss is an outcome color, `--loss`).
- The collection never leaves the device. The likely-teammates read is the existing
  `communityCores` board fetch (whole board, never naming the opponent), gated on the sharing
  switch and failing silent. No new outbound call. An edited battle resends the same anonymous
  fields.
- Engine strings only in the in-battle card; no invented matchup copy.
- Stage explicit paths; commit messages: subject alone on line 1, a blank line, body, trailers;
  write the message to a file and `git commit -F`. Never kill a process you did not start.

## Rulings made while writing this plan

1. **Edit route:** `#/meta/log/<setId>/<battleId>` parses to
   `{ screen: 'meta-log', edit: { set: string; battle: string } }`; a missing or unknown battle
   opens Log a Battle normally. [Route shape.]
2. **Wide screens:** the in-battle card moves beside the list at `min-width: 900px` (one CSS rule
   on the page grid, the card column 420px). [One number.]
3. **Likely teammates ranking:** for the first slotted opponent X, score each other species by the
   sightings of cores pairing it with X (the pair's summed thirds sightings) plus the sightings of
   thirds on cores that contain X; take the top six not already slotted. [Weights.]
4. **Contribution count:** battles across all sets with `sharedAt` and not tanked. [Definition.]
5. **Your Meta's explainer copy:** "Once you log 15 battles, Teams, Counters and Build weigh
   opponents by how often you face them. Your collection never leaves this phone; battle records
   are shared anonymously unless you turn sharing off in Settings." [Copy.]
6. **Saved toast:** the app's `notify(...)` with "Win logged · N with this team" (Loss logged,
   Tanked logged), N the set's battle count after the save. [Copy.]

## Review Focus

1. **Editing a battle that was already sent:** it resends and the worker updates the same row;
   the community meta counts it once, with the new result.
2. **Editing a tanked battle to a win (or back):** `result` and `tanked` stay consistent
   (`result: null` exactly when tanked) in the store and the worker.
3. **Sharing off:** no board read for likely teammates, the contribution line reads "Sharing is
   off", and an edit does not try to send.
4. **A result chip for a battle in a closed set or an earlier season:** edit mode still finds and
   saves it (search every set by id), and returns to Your Meta.
5. **The search with the card open on a phone:** the input stays visible below the sticky header.

- [ ] **Step 1: Failing tests**
  - `parseHash('#/meta/log/s1/b1')` gives `{ screen: 'meta-log', edit: { set: 's1', battle: 'b1' } }`
    and `hashFor` round-trips it; `#/meta/log` still parses without `edit`.

    `logBattle` does), result (`null` when tanked) and tanked; keeps `id`, `at` and the team;

    runs after it (spy, as the existing logBattle test checks sync).

- [ ] **Step 2: Implement**

```ts
// apps/web/src/state/contribution.ts
import type { BattleSet } from '@pickthree/engine';

/** Battles in the community meta: sent (stamped) and not tanked, which the meta never counts. */
export function contributedCount(sets: readonly BattleSet[]): number {
  let n = 0;
  for (const s of sets) {
    for (const b of s.battles) {
      if (b.sharedAt && !b.tanked) {
        n += 1;
      }
    }
  }
  return n;
}
```

`editBattle` mirrors `logBattle` (inside `serialized`, `persistSets([...])`), finding the set by
id among all sets (`setsRef.current`), then the battle by id; it builds the replacement with the
same opponent normalization as `logBattle` (extract that normalization into one local function
both use), `{ ...old, opponents, result: tanked ? null : result, tanked }` without `sharedAt`, and
calls `shareSync()` after a successful persist (check how `logBattle`'s caller triggers sync
today and do the same).
